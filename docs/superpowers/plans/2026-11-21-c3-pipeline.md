# C3 Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Xây pipeline Python chạy lại được: thu thập PR Java → làm sạch nhận xét người → 3 mô hình AI review → giám khảo LLM so khớp → chỉ số, khoảng tin cậy, kiểm định → công cụ chấm tay, kèm kết quả dạng bảng/biểu đồ.

**Architecture:** Gói `c3` với mỗi bước là một module nhỏ, giao tiếp qua các dataclass trong `models.py` và file JSON dưới `data/`. Mọi lời gọi LLM đi qua một client có cache trên đĩa (lưu phản hồi thô để tái lập, và để chạy lại không tốn tiền). Thống kê tách khỏi I/O để kiểm thử bằng số liệu giả.

**Tech Stack:** Python ≥ 3.11, httpx, anthropic, openai (DeepSeek qua endpoint tương thích OpenAI), numpy, pandas, scipy, statsmodels, scikit-learn, matplotlib, python-dotenv, pytest.

**Spec:** `docs/specs/2026-11-21-c3-ai-code-review-design.md` (đọc kèm `docs/related-work.md`).

## Global Constraints

- Dự án được review: **Java**; chỉ file `.java` cho cả đầu vào AI lẫn đáp án; bỏ nhận xét ở phía code cũ (LEFT).
- Script viết bằng **Python**; khóa API (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `DEEPSEEK_API_KEY`, `GITHUB_TOKEN`) chỉ đọc từ `.env`, không commit.
- Quy mô: **~100 PR** từ **2–3 dự án**, lấy mẫu ngẫu nhiên với **seed cố định `20261121`**; PR đã merge, ≤ **500** dòng thay đổi trong `.java`, ≥ **2** nhận xét có thể hành động.
- Nhận xét "thực chất": người viết, ≥ **10 từ**, có tham chiếu code hoặc từ khóa nội dung; loại PR có > **30%** nhận xét từ bot.
- AI review: 1 prompt dùng chung cho 3 mô hình, **1 lần mỗi PR**, temperature **0** nếu mô hình hỗ trợ; lưu phản hồi thô; diff là toàn bộ PR (merge-base → commit của **vòng review đầu tiên**); chỉ giữ nhận xét người trên chính commit đó.
- Danh mục 6 loại (id cố định): `logic_bug`, `error_handling`, `performance`, `design_maintainability`, `testing`, `style_naming_docs`. Bản "bỏ nitpick/phong cách" = bỏ loại `style_naming_docs`.
- Giám khảo chính Claude, giám khảo thứ hai GPT (chỉ trên tập kiểm chứng ~20% PR). Ngưỡng kappa ≥ **0,6**.
- Mẫu nhiễu: **50 góp ý không khớp cho mỗi mô hình**, seed cố định, ẩn tên mô hình, mỗi mục giao cho **đúng 2 người**.
- Khoảng tin cậy **95%**, bootstrap **theo PR**. So sánh mô hình: **Cochran's Q** rồi **McNemar** từng cặp, hiệu chỉnh **Holm**, kèm odds ratio.

## Review Focus

1. Mô hình trả JSON bọc trong ```json … ``` hoặc kèm lời dẫn → vẫn phải đọc được; hỏng hẳn thì thử lại, rồi đánh dấu lỗi, không tính thành "AI không góp ý gì".
2. Nhận xét người có `line = null` (vị trí lỗi thời) hoặc nằm file không phải `.java` → bị loại và đếm lý do, không làm hỏng việc ghép.
3. Một nhận xét người được nhiều góp ý AI cùng khớp → recall chỉ đếm 1 lần; một góp ý AI khớp nhiều nhận xét → vẫn chỉ là 1 góp ý "đã khớp".
4. AI không đưa ra góp ý nào cho một PR → không gọi giám khảo, tỉ lệ không khớp gộp vẫn tính đúng, không chia cho 0.
5. Kappa khi hai người chấm đồng ý 100% chỉ với một nhãn → trả 1,0 chứ không phải NaN.
